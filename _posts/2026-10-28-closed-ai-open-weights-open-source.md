모델을 내려받아 내 서버에서 실행할 수 있다면 오픈소스라고 불러도 될까?

가중치가 공개돼 있다는 사실만으로는 판단하기 어렵다. 실행과 파인튜닝은 가능해도 어떤 데이터로 어떻게 학습했는지 확인할 수 없을 수 있고, 사용이나 재배포에 별도의 제한이 붙기도 한다.

**Closed AI, Open Weights, Open Source AI는 성능 등급이 아니라 공개 범위와 사용 권한을 구분하는 관점이다.**

이 글은 2026년 10월 28일 확인한 자료를 기준으로 작성했다. 성능 수치는 공개 평가에서 가져왔으며 직접 모델을 실행한 실험 결과가 아니다.

## 먼저 용어의 기준을 정한다

Closed AI는 여기서 가중치를 공개하지 않고 서비스나 API로 제공하는 모델을 뜻한다. 회사 전체를 분류하는 말은 아니다. 같은 회사가 비공개 모델과 공개 가중치 모델을 함께 제공할 수도 있다.

Open Weights는 학습된 파라미터를 제공해 사용자가 직접 실행하거나 수정할 수 있게 하는 접근이다. 라이선스에 따라 가능한 사용 범위는 달라진다.

“True Open Source”는 별도로 합의된 공식 등급명이 아니다. 이 글에서는 [OSI의 Open Source AI Definition 1.0](https://opensource.org/ai/open-source-ai-definition)을 기준점으로 삼고, 학습 코드와 데이터 정보까지 폭넓게 제공하는 접근을 완전 공개형이라고 설명한다.

OSI는 사용·연구·수정·공유의 자유와 함께, 수정에 필요한 형태의 코드·파라미터·데이터 정보를 요구한다. 모든 원본 데이터를 반드시 재배포해야 한다는 뜻은 아니다. 공유할 수 없는 데이터도 출처와 특성, 선별·처리 방식 등 필요한 정보를 설명해야 한다.

## 공개 범위를 비교하면

| 확인 항목 | Closed AI | Open Weights | 완전 공개형 접근 |
|---|---|---|---|
| 모델 가중치 | 비공개 | 공개 | 공개 |
| 전체 학습 코드 | 보통 비공개 | 제공을 보장하지 않음 | 공개 범위의 핵심 요소 |
| 학습 데이터 정보 | 제한적 공개가 일반적 | 모델마다 다름 | 재구성에 충분한 정보 요구 |
| 자체 서버 실행 | 일반적으로 불가 | 라이선스·하드웨어 조건하에 가능 | 가능 |
| 직접 파인튜닝 | 업체가 지원하는 범위 | 가능 | 가능 |
| 학습 과정 검토 | 제한적 | 공개된 자료 범위 | 코드와 데이터 정보까지 검토 가능 |
| 사용 조건 | 서비스 계약·약관 | 모델별 라이선스 | 자유로운 사용·수정·공유를 허용하는 조건 |

이 표는 세 범주를 완전히 배타적인 집합으로 보려는 것이 아니다. 완전 공개형 모델도 가중치를 제공한다는 의미에서는 Open Weights에 포함된다. 여기서는 가중치 공개에서 더 나아가 무엇을 제공하는지 비교하기 위해 구분했다.

또한 공개와 재현 가능성은 같은 말이 아니다. 자료가 충분해도 사전학습을 다시 수행할 계산 자원이 필요하고, 실행 환경과 학습의 변동 때문에 원본과 비트 단위로 같은 모델이 나오지 않을 수 있다.

## 대표 모델은 이름보다 개별 배포물을 본다

| 범주 | 대표 사례 | 확인할 점 |
|---|---|---|
| Closed AI | Claude Opus 5.5, GPT-6 Astra | 가중치 대신 제공 서비스로 사용하는 모델 |
| Open Weights | Qwen3-32B | 모델 카드에 Apache 2.0 명시 |
| Open Weights | Llama 4 | 자체 Community License 적용 |
| 완전 공개형 | Ai2 Olmo 3 계열 | 가중치·코드·데이터와 학습 과정 공개 |
| 완전 공개형 | Swiss AI Apertus | 학습 데이터·코드·정렬 원칙까지 공개하는 접근 |

Olmo와 Apertus의 분류는 제작자가 공개한 자료와 설명을 근거로 한 예시이며, 이 글에서 별도의 OSI 인증 여부를 판정했다는 뜻은 아니다. [Ai2의 Olmo 설명](https://allenai.org/blog/olmo3)과 [Apertus FAQ](https://www.apertus-ai.org/docs/faq/)에서 공개 범위를 확인할 수 있다.

계열 이름만으로 라이선스나 공개 수준을 확정하면 안 된다. Base, Instruct, Think, 파생·증류 모델마다 공개 자료와 조건이 달라질 수 있다. 실제로 도입할 체크포인트의 모델 카드와 라이선스를 확인해야 한다.

## Open Weights도 사용 조건은 서로 다르다

[Qwen3-32B 모델 카드](https://huggingface.co/Qwen/Qwen3-32B)에는 Apache 2.0 라이선스가 표시돼 있다. 반면 [Llama 4 라이선스](https://github.com/meta-llama/llama-models/blob/main/models/llama4/LICENSE)는 별도의 조건을 둔다. 예를 들어 해당 버전 출시 시점을 기준으로 일정 규모를 넘는 월간 활성 이용자를 가진 사업자에는 별도 허가 조건이 있다.

여기서 구분해야 할 질문은 두 개다.

1. 이 배포물을 어떤 조건으로 사용·수정·재배포할 수 있는가?
2. 학습 과정을 이해하고 변경하는 데 필요한 자료가 얼마나 제공되는가?

가중치의 라이선스가 개방적이어도 전체 학습 데이터와 코드가 함께 제공된다는 뜻은 아니다. 반대로 많은 기술 문서를 공개했더라도 이용 제한이 있다면 사용 자유의 측면에서 차이가 있다.

실무에서는 라이선스 명칭만 기록하기보다 적용 대상, 버전, 재배포 조건과 고지 의무를 함께 확인하는 편이 좋다. 모델 파일의 조건과 호스팅 API의 이용약관도 구분해야 한다.

## 성능 비교 1: 상위 Closed와 Open Weights 모델

[Artificial Analysis 모델 비교 페이지](https://artificialanalysis.ai/models/)에서 확인한 **Intelligence Index v5.0**의 일부다. 확인일은 2026년 10월 28일이며, 점수는 정답률이 아닌 종합 지수다.

| 모델 | 공개 형태 | 원문 추론 설정 | 지수 |
|---|---|---|---:|
| Claude Opus 5.5 | Closed | Max, Default Fallback | 58 |
| GPT-6 Astra | Closed | Max | 57 |
| DeepSeek V4.1 Flash 1017 | Open Weights | Max | 32 |
| GLM-5.3 | Open Weights | Max | 32 |

같은 평가 제공자의 동일 지수에서 발췌했지만, 동일 GPU나 동일 토큰·비용 예산으로 맞춘 실험이라는 뜻은 아니다. 추론 설정과 평가 실행 환경도 결과의 일부다.

이 표는 해당 평가에서 상위 Closed 모델의 점수가 높았음을 보여준다. 공개 방식이 성능 차이의 원인이라고 입증하지는 않는다. 모델 규모, 학습 자원, 추론 비용 등이 함께 다르다. 58점 모델이 32점 모델보다 모든 작업에서 약 1.8배 좋다고 해석할 수도 없다.

지수 버전이 바뀌면 구성 과제도 달라지므로 v4 계열 점수와 직접 비교하지 않는다. 동적으로 갱신되는 페이지인 만큼 도입 검토 시에는 확인일과 설정을 다시 기록해야 한다.

## 성능 비교 2: 비슷한 규모의 완전 공개형 모델

다음은 [Ai2의 Olmo 3 발표문](https://allenai.org/blog/olmo3)에 실린 비교표의 일부다. 원문 최초 발표일은 2025년 11월 20일이며, 아래 값은 Olmo 3.1이 아닌 **Olmo 3-Think 32B** 행이다.

| 평가 | Olmo 3-Think 32B | Qwen3-32B |
|---|---:|---:|
| AIME 2025 — 수학 | 72.5 | 70.9 |
| HumanEvalPlus — 코드 생성 | 91.4 | 91.2 |
| LiveCodeBench v3 — 코딩 | 83.5 | 90.2 |
| IFEval — 지시 준수 | 89.0 | 86.5 |
| GPQA — 전문 지식·추론 | 58.1 | 67.3 |

**모델 제작자의 자체 보고**이며 독립 재현 결과는 아니다. 비슷한 파라미터 규모의 비교지만 학습량과 추론 예산까지 동일하다는 뜻은 아니다. 세부 실행 조건은 원문의 기술 보고서와 평가 자료를 확인해야 한다.

Olmo가 높은 항목과 Qwen이 높은 항목이 함께 있다. 작은 점수 차이만으로 통계적으로 우월하다고 단정할 수 없으며, 공개 수준만으로 성능 순위를 정할 수 없다는 예로 읽는 편이 적절하다.

위의 Artificial Analysis 지수와 이 표의 개별 벤치마크 점수는 서로 다른 척도다. 두 표를 합쳐 세 범주의 통합 순위를 만들지 않는다. Apertus에 대해서는 여기서 같은 조건의 비교 수치를 확보하지 않았으므로 점수를 추정해 넣지 않았다.

## 실제 선택에서는 무엇을 먼저 볼까

아래는 벤치마크의 결론이 아니라, 시스템을 설계할 때 사용할 수 있는 판단 기준이다.

| 우선하는 목표 | 먼저 검토할 방향 |
|---|---|
| 빠른 도입과 적은 인프라 운영 부담 | 관리형 API |
| 자체 환경 실행과 체크포인트 고정 | 공개 가중치 모델 |
| 학습 데이터 구성·처리 과정 연구 | 코드와 데이터 정보가 함께 공개된 모델 |
| 한국어 문서 답변 품질 | 실제 질문과 문서에 대한 별도 평가 |
| 비용 절감 | 호출량과 GPU 사용률을 포함한 총비용 비교 |

Closed/Open은 모델의 공개 특성이고, API/자체 호스팅은 배포 방식이다. 공개 가중치 모델도 외부 API로 사용할 수 있다. API를 사용한다는 사실만으로 Closed 모델이라고 분류하면 안 된다.

자체 서버에서 실행하면 버전과 배포 환경을 직접 관리할 수 있지만, 패치·관측·장애 복구·용량 관리도 맡아야 한다. 외부로 데이터를 보내지 않는 구성은 가능해도 자체 호스팅만으로 보안이 자동 확보되는 것은 아니다. 로그와 접근 권한, 관리 도구의 외부 통신까지 설계해야 한다.

비용 역시 가중치 다운로드 가격과 운영 비용을 구분한다. GPU와 메모리, 유휴 시간, 병렬 처리, 운영 인력을 합쳐야 한다. 양자화로 메모리를 줄였다면 원본 벤치마크 점수를 그대로 자신의 배포 성능으로 사용할 수 없다.

## RAG를 만들 때도 같은 구분이 필요하다

가상의 도서관 안내 서비스를 만든다고 하자. 공개 모델을 사용하더라도 검색이 엉뚱한 시설 안내를 가져오면 답변이 틀릴 수 있다. 반대로 높은 종합 점수를 가진 Closed 모델도 자료에 없는 운영 조건을 덧붙일 수 있다.

따라서 [RAG의 검색·생성 흐름](/posts/rag-retrieval-grounded-generation/)을 분리해 평가하고, 사용할 모델 버전과 추론 설정을 고정해야 한다. [LLM-as-Judge 평가](/posts/ai-search-keyword-model-benchmark-luna/)를 보조 수단으로 사용하더라도 평가자 자체의 오류를 점검할 필요가 있다.

처음에는 같은 문서와 질문으로 필요한 품질을 만족하는지 확인한다. 그다음 지연·비용·권한·운영 조건을 비교한다. 학습 과정의 연구가 목적이라면 데이터와 코드 공개 수준의 비중이 커지고, 서비스 운영이 목적이라면 배포 환경과 장애 대응 능력도 중요해진다.

모델 선택에서는 **공개 범위, 사용 권한, 과제별 품질, 운영 비용을 별도의 축으로 보는 것**이 도움이 된다. “오픈소스라서 좋다” 또는 “비공개라서 성능이 좋다”라는 한 문장으로는 이 선택을 설명하기 어렵다.
